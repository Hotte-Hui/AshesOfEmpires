## Rendering notes for integration
* **Viewport:** works in any viewport size; designed for the 642×362 world SubViewport (horizon at y = H/2 + 56, i.e. 236/237). The level sets MSAA/FXAA/TAA/debanding off and 3D scale 1.0 on its viewport and restores the previous values when it leaves the tree.
* **Colour pipeline:** opaque pass in linear HDR → post quad converts to sRGB, does all pixel-art work there, snaps to the berlin palette and writes linear back; tonemapper LINEAR, exposure 1 → captured frames contain **only berlin palette colours** (verified). The lead's 2D Grade layer still runs on top: with the `hall_3d` key (not in `data/grades.json` yet) `Game._apply_grade()` falls back to `default` (vignette 0.2), which pushes edge pixels slightly off-palette; an identity entry `"hall_3d": {"vignette": 0.0, "grain": 0.0, "palette_strength": 0.0}` keeps the output exact.
* **Material flags** live in ROUGHNESS → normal-roughness buffer w channel. Godot **4.7.2 stores roughness unmodified** (verified with `debug_view = 1`: 0 / 0.3 / 0.55 / 0.75 / 1.0 read back exactly), unlike 4.2-era builds (`legacy_roughness_packing` uniform switches the old 127/255 + dynamic-flip decoding back on). Bands: < 0.2 architecture, 0.2–0.45 architecture allowed to use the patina ramp (dome), 0.5–0.65 people, 0.68–0.9 emissive, > 0.92 wires.
* **Render layers:** 1 = exterior, 2 = archive interior (lit only by the desk lamp / window spill), 4 = people (character key lights `FamilyKey`, `GuardKey` affect only this layer so figures read without blowing out the facades).
* **Camera rotation must stay identity**: sky/fog/smoke mattes are screen-space and only follow the lens shift. A camera shake should be applied as a lens shift (frustum offset) or at display level, not as rotation.
* **Cues:** `cue(key)` fires at 0.15 s (archive), 1.6 s (tram bell), 3.6 s and 8.4 s (loudspeaker), 9.55 s (story window closes). The lead's `_cin_hall()` additionally shows `cinematic.hall_reveal`.

## Verification (2026-11-04, RTX 4090, Windows 11)
* `HallPreview` windowed run: 4 captures at t = 1/4/7/10 s; **every captured frame uses 35 colours, 0 outside `pg.PALETTES['berlin']`** (checked with Python against `pg.py`).
* Performance (640×360, captured by the harness while playing): frame delta avg 4.29 ms (vsync-bound, 240 Hz display; spikes up to ~74 ms are the frames that save PNGs), **viewport GPU render time 0.18 ms avg / 0.21 ms max**, viewport CPU render time 0.14 ms avg, 61–71 draw calls, ~74 k primitives per frame (incl. 4 directional shadow cascades), video memory 106 MB for the whole process. `Performance.TIME_PROCESS` in 4.7.2 refreshes about once per second and is reported as logged.
* Motion: consecutive 60 fps frames in h2/h3 (snow off) differ in 376–1835 of 230 400 pixels (≤ 0.8 %), almost all at near-geometry edges and wires; the hall region changes by < 90 px per frame (`_preview/crawl_diff.png`). h1 (crane) changes ~14 % per frame as expected for the move.
* `--selftest` (headless): camera is current, viewport AA disabled and restored, `finished` exactly once for skip/skip, again exactly once for a full (time-scaled) play, no extra emission on skip after the end, all 5 cues in order, `set_people_sprites` before `_ready` and at runtime, all cue keys present in `de_hall.json` → **PASS**.
* Iterations on weak areas (see `_preview/iterations/`): composition (hall hidden by tenements → street opens onto the plaza; family scale vs. door; obstructing lamp post/pole removed; family moved beside the door, character key light), floodlights (round pools → vertical wall-washes; toon quantisation changed to luminance-aware), dome (roughness-flag decoding fixed for 4.7.2, patina reserved/less fogged, sky gaps under the drum/lantern cornices closed, rim applied after fog), sky (torn fragments → stratus streaks; bead-like smoke → bands), street (dashed slush → continuous ruts, crate-like snow banks → wedges).

## Known limitations / not verified
* Not run inside the lead's `Main.tscn`/`Game._cin_hall()` end-to-end (that is the lead's integration); verified in the harness viewport (640×360) and, for logic, in a 642×362 SubViewport.
* Placeholder people are simple; the real `assets/characters/*` sheets (present at the time of writing) are used automatically.
* The h1 crane moves fast (it is a 3 s crane through a window); pixels of near facades necessarily move a lot during h1.
* Directional sun shadows over 2.6 km are coarse; the look does not depend on them (sun is behind the hall).
